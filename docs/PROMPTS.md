# 可复制的任务指令

## 看懂项目
阅读 README.md、AGENTS.md 和程序入口，说明目录结构、运行方式和当前限制。先运行现有测试，暂不修改代码。

## 加一个功能
给任务清单增加【功能】。用户场景是【场景】。验收标准是【可观察的结果】。保留原有命令，补充必要的行为测试并运行。交付时说明改动和限制。

## 修复问题
执行【完整命令】时出现【实际结果】，期望是【期望结果】。先复现，再修复原因，添加能防止问题再次出现的测试，最后运行相关测试。不要顺带重构整个项目。

## 检查修改
审查当前修改，重点找实际错误、数据丢失风险和缺少的关键测试。按影响排序，指出位置和触发条件。不确定的情况说明假设，先不修改代码。

## 推进真实项目
阅读 docs/PROJECT_BRIEF.md，指出阻碍实现的关键信息。先完成不依赖缺失信息的部分，把第一版范围控制在一个能运行的主要流程。不要编造调研和效果数据。
